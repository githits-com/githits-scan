# Backlog

## Git source coverage without actionable warnings

Ordered Scan follow-on after native lifecycle adoption. Ordinary Git-sourced
dependencies are supported business inputs. Expected registry-check and Git graph
or captured-binding limits must become concise informational coverage footnotes,
without independently producing exit 1 or Action warnings. Factual incompleteness
must remain machine-readable. This behavior is not implemented by the native
lifecycle collection-limit change.

Scan owns classification and attention in its pure audit assessment; its command
view owns human notes and the compact JSON distinction between informational
coverage and actionable issues. The current report model already preserves the
source, resolution and exclusion causes. Before implementation, qualify their
placement in report v3; the supplied Git-only producer evidence used report v2.
Do not introduce a legacy reader or infer Git from missing coordinates, names or
paths.

Acceptance criteria:

- Only the explicit causes `git_registry_checks_not_supported`,
  `git_dependency_graph_unavailable` and `git_source_binding_unavailable` qualify
  as expected Git limitations; unavailable captured binding stays incomplete.
- Git-only limits retain coverage facts, render a concise informational footnote,
  and independently produce no attention or exit 1. Human output gives no
  unsupported repair or retry instruction.
- Actual lookup failures, `recorded_git_source_differs`, malformed input,
  non-Git gaps and unfamiliar causes remain actionable. Mixed reason lists retain
  every independent actionable cause, including `umbrella_members_not_captured`.
- Native findings/unknowns, advisories and other independent findings keep their
  existing attention behavior. Tests cover informational-only, mixed,
  contradictory and unfamiliar cases through online, saved replay and explanation
  output without paid live scans.
- Settle and document the compact JSON attention/information contract with the
  separately authorized Action handoff before advancing its Scan pin. Scan alone
  does not establish Action's independent diff-qualification behavior.
